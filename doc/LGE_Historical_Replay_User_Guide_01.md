Дата: 2026-07-26  
Проєкт: LavrGPT05 / LGE  
Статус: робоча чернетка для RoadMap93

---

# 1. Для чого потрібен Historical Replay

Historical Replay дозволяє програвати історичні ринкові бари у WSP так,
ніби вони надходять послідовно в реальному часі.

Поточний режим призначений для:

1. перевірки графіка;
2. перевірки warm-up;
3. перевірки spread guard;
4. перевірки сигналів;
5. перевірки Pause, Step і Speed;
6. повторюваної відладки алгоритму.

Поточний Historical Replay не виконує реальні брокерські ордери.

---

# 2. Де зберігати CSV-файл

LGE не копіює CSV у свою папку. Він читає файл безпосередньо з місця,
яке вибрано кнопкою «Огляд...».

Після збереження налаштувань LGE записує у Session абсолютний шлях до
файлу.

Канонічна структура для історії, завантаженої з брокера:

```text
D:\LavrGPT\LavrGPT05\data\history\CTRADER\EURUSD\M15\
D:\LavrGPT\LavrGPT05\data\history\CTRADER\GBPUSD\M15\
D:\LavrGPT\LavrGPT05\data\history\IB\EURUSD\M15\
D:\LavrGPT\LavrGPT05\data\history\IB\GBPUSD\H1\
```

Ідентифікатор рахунку в шлях не додається. Історичні OHLC-бари
належать broker + symbol + timeframe, а не конкретному рахунку.

Канонічна назва файлу:

```text
YYYY-MM-DD_YYYY-MM-DD_BROKER_SYMBOL_TIMEFRAME.csv
```

Приклади:

```text
2026-06-26_2026-07-26_CTRADER_GBPUSD_M15.csv
2026-06-26_2026-07-26_IB_GBPUSD_M15.csv
2026-01-01_2026-07-26_IB_EURUSD_H1.csv
```

На початку назви стоять фактичні дати першого й останнього барів.
Тому файли природно сортуються за періодом історії. Дата завантаження
до назви не додається.

Якщо файл перемістити, перейменувати або видалити, Replay не запуститься.

## 2.1. Окремі форми завантаження і тестування

LGE розділяє дві різні операції:

```text
Історичні дані
    -> запит до IB або cTrader
    -> дати завантаження і timezone запиту
    -> створення канонічного CSV

Налаштування Replay
    -> вибір готового CSV
    -> точний початок і кінець тесту
    -> формат CSV, timezone джерела і spread
```

Період брокерського запиту, фактичний період отриманого CSV і період
тесту Replay можуть відрізнятися.

Наприклад, користувач запитує:

```text
2026-01-01 — 2026-07-27
```

але брокер повертає доступні бари лише за період:

```text
2026-05-14T07:45:00Z — 2026-07-27T09:30:00Z
```

Тоді остаточна назва файла буде:

```text
2026-05-14_2026-07-27_CTRADER_EURUSD_M15.csv
```

## 2.2. Як завантажити історію з cTrader або IB

Перед завантаженням відповідний брокер має бути підключений у LGE,
а WSP має бути зупинений.

1. Відкрийте потрібний WSP.
2. Натисніть `Історичні дані`.
3. Перевірте broker, account, symbol і timeframe.
4. Виберіть дату початку та дату завершення.
5. Виберіть часовий пояс періоду завантаження. Default — `UTC`.
6. Перевірте заплановану назву CSV і папку збереження.
7. Натисніть `Завантажити`.
8. Дочекайтеся повідомлення з кількістю барів і фактичним періодом.
9. Натисніть `Використати для Replay`, якщо цей файл треба одразу
   підключити до поточного WSP.

Для cTrader CSV зберігається у:

```text
data/history/CTRADER/<SYMBOL>/<TIMEFRAME>/
```

Для IB CSV зберігається у:

```text
data/history/IB/<SYMBOL>/<TIMEFRAME>/
```

IB Forex використовує `MIDPOINT`. Якщо IB не повертає реальний volume,
у CSV записується `0`.

Великі періоди можуть завантажуватися кількома broker-запитами.
Індикатор у формі показує, що завантаження триває.


# 3. Обов'язкові колонки CSV

CSV повинен мати заголовок і щонайменше такі колонки:

```text
time
open
high
low
close
```

Для часу також підтримуються назви:

```text
timestamp
datetime
date
```

Назви колонок не залежать від регістру.

Мінімальний приклад:

```csv
time,open,high,low,close
2026-07-20 08:00:00,1.1400,1.1410,1.1390,1.1405
2026-07-20 08:15:00,1.1405,1.1415,1.1400,1.1410
2026-07-20 08:30:00,1.1410,1.1420,1.1405,1.1415
```

---

# 4. Необов'язкові колонки

Підтримуються:

```text
volume
vol
tick_volume
bid
ask
spread
```

Правила:

1. `bid` і `ask` повинні бути або обидва, або жодного;
2. якщо є `bid`, `ask` і `spread`, то `spread` має дорівнювати
   `ask - bid`;
3. якщо `bid` і `ask` відсутні, LGE обчислює їх від `close`;
4. для обчислення використовується `spread` із рядка або значення
   «Спред за замовчуванням» із діалогу;
5. якщо `volume` відсутній, використовується `0`.

Приклад із готовими котируваннями:

```csv
time,open,high,low,close,volume,bid,ask
2026-07-20 08:00:00,1.1400,1.1410,1.1390,1.1405,100,1.14044,1.14056
```

---

# 5. Формати часу

Підтримується ISO-формат:

```text
2026-07-20T08:15:00Z
2026-07-20T08:15:00+00:00
2026-07-20 08:15:00
```

Також підтримуються:

```text
20.07.2026 08:15:00
20.07.2026 08:15
20/07/2026 08:15:00
20/07/2026 08:15
2026.07.20 08:15:00
2026.07.20 08:15
```

Якщо timestamp містить timezone або `Z`, він використовується напряму.

Якщо timestamp не містить timezone, LGE трактує його у часовому поясі,
який вибрано в полі «Часовий пояс джерела CSV».

Для файлів, уже записаних в UTC, вибирайте:

```text
UTC
```

---

# 6. Роздільники

Підтримуються:

```text
кома         ,
крапка з комою ;
табуляція    Tab
вертикальна риска |
```

Можна вибрати «Визначати автоматично».

Для десяткових чисел підтримуються:

```text
крапка .
кома   ,
```

Якщо числа мають десяткову кому, практично краще використовувати
роздільник колонок `;`.

Приклад:

```csv
time;open;high;low;close
20.07.2026 08:00:00;1,1400;1,1410;1,1390;1,1405
```

У діалозі для такого файлу треба вибрати:

```text
Роздільник стовпців: Крапка з комою (;)
Десятковий роздільник: Кома (,)
```

---

# 7. Вимоги до якості даних

Loader працює fail-closed.

Replay буде заблокований, якщо:

1. немає обов'язкової колонки;
2. timestamp неправильний;
3. timestamps не йдуть строго за зростанням;
4. є два однакові timestamps;
5. OHLC неправильний;
6. число не читається;
7. значення не є finite;
8. `bid` є без `ask` або навпаки;
9. `spread` не дорівнює `ask - bid`;
10. у рядку є зайві CSV-колонки;
11. вибраний період не містить жодного рядка.

LGE не сортує пошкоджені дані мовчки.

---

# 8. Як налаштувати Replay у WSP

1. Створіть або відкрийте WSP.
2. Переконайтеся, що runtime має стан `STOPPED`.
3. У полі «Режим передачі даних» виберіть «Історичний огляд».
4. Натисніть «Налаштування Replay».
5. У полі «Тип джерела» виберіть «Історичний CSV».
6. Введіть зрозумілу назву джерела.
7. Натисніть «Огляд...» і виберіть готовий CSV.
8. За потреби звузьте точний початок і кінець тесту Replay.
9. Виберіть часовий пояс timestamps CSV без власної timezone.
10. Виберіть роздільник колонок і десятковий роздільник.
11. Вкажіть spread за замовчуванням.
12. Натисніть «Зберегти».

Налаштування завантаження історії та налаштування Replay зберігаються
окремо для кожного WSP.


# 9. Як запустити Replay

1. Натисніть `START`.
2. LGE завантажить CSV.
3. Runtime пройде послідовність:

```text
LOAD_DATA
    -> WARMUP
    -> WAIT_SPREAD
    -> READY
    -> RUNNING
```

4. Графік почне отримувати бари.
5. Журнал покаже завантаження історії, warm-up і spread guard.
6. Вкладка «Сигнали» покаже accepted або rejected signals.

Якщо CSV не завантажується, synthetic fallback не використовується.
WSP переходить у `ERROR` із точною причиною.

---

# 10. Pause, Step і Speed

## Pause

Зупиняє автоматичний перехід до наступного market event.

## Step

Працює лише після Pause. Передає рівно один наступний бар.

## Speed

Підтримуються:

```text
1x
2x
5x
10x
```

Speed змінює темп автоматичного Replay, але не змінює порядок подій.

Один і той самий CSV із тими самими налаштуваннями повинен дати
однаковий результат при повторному запуску.

# 11. Quality report

Після завантаження WSP показує короткий звіт, наприклад:

```text
CSV 5/8 • пропущено 3 • розривів 1 • котирувань 5
```

Значення:

```text
5/8
```

Прийнято 5 рядків із 8 прочитаних.

```text
пропущено 3
```

Три рядки не потрапили у вибраний період.

```text
розривів 1
```

Знайдено один часовий розрив, більший за timeframe WSP.

```text
котирувань 5
```

Для п'яти рядків `bid/ask` були обчислені від `close` і spread.

Повний звіт також записується у журнал WSP.

# 12. Що зберігається після перезапуску LGE

Зберігаються:

1. тип джерела;
2. абсолютний шлях до CSV;
3. назва джерела;
4. початок і кінець періоду;
5. timezone;
6. роздільники;
7. default spread;
8. Replay speed.

Не відновлюються як активний runtime:

1. стан `RUNNING`;
2. Replay cursor;
3. попередні сигнали;
4. попередній графік;
5. market-event processing.

Після restart WSP починає зі `STOPPED` і не запускається автоматично.

---

# 13. Як відновитися після ERROR

1. Натисніть `STOP`.
2. WSP повернеться у `STOPPED`.
3. Відкрийте «Налаштування Replay».
4. Виправте шлях, період, timezone, роздільник або CSV.
5. Збережіть налаштування.
6. Натисніть `START` повторно.

---

# 14. Швидка перевірка перед Start

```text
[ ] WSP має правильні broker, account, symbol і timeframe
[ ] Режим передачі даних = Історичний огляд
[ ] Тип джерела = Історичний CSV
[ ] CSV-файл існує
[ ] Обов'язкові колонки присутні
[ ] Timestamps строго зростають
[ ] Timezone вибраний правильно
[ ] Роздільник колонок правильний
[ ] Десятковий роздільник правильний
[ ] Spread заданий правильно
[ ] Runtime має стан STOPPED
```

---

# 15. Поточне обмеження

Historical Replay уже підключений до runtime, графіка, журналу,
warm-up, spread guard і сигналів.

Повний RailAlgorithm, MACD/Alligator та реальне виконання broker orders
ще не входять до поточного користувацького сценарію.
